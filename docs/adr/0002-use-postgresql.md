# 0002. Използване на PostgreSQL за бележките

**Status / Статус:** Accepted

## Context / Контекст

Notes API трябва да запазва бележките след рестарт и пресъздаване
на контейнера. Съхраняването само в паметта губи данните.
Приложението вече поддържа PostgreSQL чрез DATABASE_URL.

## Options / Варианти

1. Съхранение в паметта
   - Плюсове: лесна настройка, без допълнителна услуга.
   - Минуси: данните се губят при рестарт.

2. SQLite
   - Плюсове: съхранява данните във файл, без отделен сървър.
   - Минуси: изисква промени в приложението и има ограничения
     при множество едновременни записи.

3. PostgreSQL
   - Плюсове: поддържа се от приложението, транзакции и едновременен достъп.
   - Минуси: изисква отделна услуга, настройки и управление на парола.

## Decision / Решение

Използваме PostgreSQL 17 с образ postgres:17-alpine като услуга db
в Docker Compose. Данните се съхраняват в именувания volume
postgres_data, монтиран към /var/lib/postgresql/data.

Приложението се свързва чрез DATABASE_URL към db:5432.
Данните за вход се задават в .env, който не се комитва.
В хранилището се пази .env.example с примерни стойности.

Healthcheck проверява готовността на PostgreSQL.
Приложението изчаква базата чрез depends_on и service_healthy.

## Consequences / Последствия

- Бележките остават след docker compose down и повторно up.
- docker compose down -v изтрива volume-а и данните.
- Необходимо е да поддържаме услугата db и правилни данни за вход.
- Именуваният volume не замества резервното копие на базата.
- Adminer е достъпен по избор чрез профила tools.
