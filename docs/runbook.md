# Runbook

Този файл описва как се стартира, проверява и тества приложението Notes API, както и какво трябва да направим при възникване на проблем.

## Start locally / Локално стартиране

За да стартираме приложението локално без Docker, отваряме терминал в основната папка на проекта и изпълняваме:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Първо създаваме виртуална среда, след което я активираме. Инсталираме необходимите библиотеки и стартираме приложението на порт 8000.

## Check that it works / Проверка, че работи

За да проверим дали приложението работи, отваряме в браузъра:

`http://localhost:8000/health`

Очакваният резултат е:

```json
{"status":"ok"}
```

Можем да направим проверката и през терминала:

```bash
curl http://localhost:8000/health
```

Ако използваме GitHub Codespaces, отваряме порт 8000 от раздела Ports и добавяме `/health` в края на предоставения адрес.

Ако получим `{"status":"ok"}`, приложението работи успешно.

## Run the tests / Тестове

За да изпълним автоматизираните тестове, първо активираме виртуалната среда и инсталираме необходимите библиотеки:

```bash
source .venv/bin/activate
pip install -r requirements.txt
```

Ако pytest не е инсталиран, го добавяме:

```bash
pip install pytest
```

След това стартираме тестовете:

```bash
python -m pytest -v
```

Командата изпълнява откритите от pytest тестове и показва резултатите от тях.

При успешно изпълнение очакваме тестовете да завършат със статус `PASSED`.

## When something breaks / Когато нещо се счупи

Ако приложението не работи, първо проверяваме следните три неща:

### 1. Проверяваме дали контейнерът работи

```bash
docker ps -a
```

Командата показва всички контейнери и техния статус.

Ако контейнерът е спрян, можем да го стартираме:

```bash
docker start notes-api-container
```

### 2. Проверяваме логовете

```bash
docker logs notes-api-container
```

Така можем да видим дали има грешки при стартиране или изпълнение на приложението.

### 3. Проверяваме дали приложението отговаря

```bash
curl -i http://localhost:8000/health
```

Ако приложението работи, трябва да получим HTTP статус `200 OK` и:

```json
{"status":"ok"}
```

Ако няма връзка, проверяваме дали порт 8000 е правилно зададен и дали приложението е стартирано.

## Стартиране с Docker

### 1. Build – изграждане на образа

```bash
docker build -t notes-api:0.3.0 .
```

Тази команда изгражда Docker образ с име `notes-api` и версия `0.3.0`.

### 2. Run – стартиране на контейнера

```bash
docker run -d --name notes-api-container -p 8000:8000 notes-api:0.3.0
```

Тази команда стартира приложението във фонов режим на порт 8000.

Приложението може да се провери на адрес:

`http://localhost:8000/health`

Очакваният резултат е:

```json
{"status":"ok"}
```

Ако контейнерът със същото име вече съществува, можем да го премахнем преди повторно стартиране:

```bash
docker rm -f notes-api-container
```

### 3. Logs – преглед на логовете

```bash
docker logs notes-api-container
```

Показва съобщенията от работата на приложението.

За да следим логовете в реално време, използваме:

```bash
docker logs -f notes-api-container
```

### 4. Stop – спиране на контейнера

```bash
docker stop notes-api-container
```

Спира работещия контейнер.

За повторно стартиране използваме:

```bash
docker start notes-api-container
```

## Заключение

С помощта на тези команди можем да стартираме приложението локално или чрез Docker, да проверим дали работи, да изпълним тестовете и да открием основни проблеми при неговото стартиране.
